Pre-UAT Validation

Every signed requirement, checked against the build

Problems sort to the top. Each one comes with the fix and a plain-language note on what the customer would hit if it shipped. Check IDs stay the same between runs, so V-07 means the same thing before and after a fix.

Test Cases

Derived from the workflow, not copied from the last customer

The generator reads what the integration does and writes the cases that integration needs. A case that a known defect would break is marked before anyone runs it, so the customer never spends an afternoon proving a bug the team already knew about.

If the workflow maps hire_date
Rehire reactivates the original user, with the new hire date
If there's a population filter
One test per excluded class: contractors, seasonal workers
If it maps worker status
Termination deactivates; leave of absence stays active
If it matches on external_id
An email change updates the user and never duplicates them
If it converts timestamps
An 11:41 PM completion keeps its calendar date
If the spec names a peak volume
A 2,500-record batch posts with rate-limit retries

The workbook

Eight tabs the customer's team can work from

Yellow cells are for the customer to fill in. Status columns are dropdowns, every state carries an icon and a label, and sign-off criteria are formulas nobody can type over.

How it runs

A deterministic script, with Claude on either side of it

The script produces the same workbook every time from the same input. Claude handles the parts that need judgement: explaining each failure to a person, making the fix on a copy, and running it again.

The spec is the source of truth

A fix changes the workflow to match what the customer signed. The generator never edits the spec to make a check pass.

Same input, same workbook

A customer-facing document shouldn't change between two runs. Test cases come from rules, so they can be reviewed and audited.

Built for more than one iPaaS

The input is a small documented shape. Supporting a real Tray, Workato or Boomi export means writing an adapter; the checks stay the same.
